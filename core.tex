\section{The public dependent core}
\label{sec:core}

\subsection{Data and roles}

Fix a finite nonempty set of roles $\Roles$. A role names the owner of a
choice. It does not prescribe an objective or an evaluation priority. We use
$K=|\Roles|$ when the number of roles matters.

Fix a pure dependent data calculus $\D$. We assume dependent products, strong
dependent sums with dependent elimination and both projections, a unit type,
finite products, and capture-avoiding substitution, with the usual
substitution and conversion rules. No sum or function $\eta$-conversion is
assumed. For the execution results below we
add the hypotheses that closed well-typed data computations are strongly
normalizing and confluent, with canonical forms for sums and functions.
These hypotheses are on the chosen data calculus; they introduce no control
operator or arbitrary truth oracle.

Write $\Gamma\vdash A:\U$ for a data type and $\Gamma\vdash a:A$ for a data
term. The context $\Gamma$ of the public core is shared: its values are
available to every endpoint. Types may depend on earlier context entries.
Universes can be stratified in $\D$; all constructions below are read at
compatible levels.

\subsection{Scripts}

\begin{definition}[Public script]
A well-formed script is generated by
\[
 G ::= \End\langle R_i\rangle_{i\in\Roles}
       \mid \Q_r(x:A).H,
 \qquad r\in\Roles,
 \tag{2}
\]
with formation rules
\[
 \frac{(\Gamma\vdash R_i:\U)_{i\in\Roles}}
      {\Gamma\vdash\End\langle R_i\rangle_i:\Script}
 \qquad
 \frac{\Gamma\vdash A:\U\qquad\Gamma,x:A\vdash H:\Script}
      {\Gamma\vdash\Q_r(x:A).H:\Script}.
 \tag{3}
\]
The binder introduces one value of $A$, owned by $r$, into every endpoint's
continuation context. At $\End$, the endpoints return their respective results;
the complete result record is exported at a public return boundary.
No endpoint sees the other terminal returns before supplying its own.
Thus \emph{public} describes the choice binders; a nontrivial terminal return
interface is a simultaneous decision stage, made explicit in
\cref{sec:composition}.
\end{definition}

The grammar is finite. Data substitution changes the types and expressions
inside a script, but does not replace its script constructors. Thus the number
$n(G)$ of choice binders is independent of the actual values selected. This
fragment permits dependent data while fixing the sequence of choice owners.
This is a restriction on direct syntax. If the data calculus can compute
types by finite case analysis, bounded-depth owner branching can be encoded
by scheduling every role at each level, using unit moves for inactive roles
and retaining the active owner for that level. Unbounded depth and recursion
are outside this fragment. Such padding is an encoding of interaction trees,
not an argument that arbitrary quantifier reorderings preserve their meaning.

The terminal family $\langle R_i\rangle_i$ records interfaces, not preferences.
Setting every $R_i=\Unit$ gives a script whose only observable data are its
choices. Setting $R_i$ to a proposition asks endpoint $i$ to return evidence of
that proposition. More general data results are equally possible.

\subsection{Endpoint types and terms}

\begin{definition}[Local interpretation]
For $i\in\Roles$, define the data type $\Local{i}{G}$ by
\[
 \Local{i}{\End\langle R_j\rangle_j}=R_i,
 \qquad
 \Local{i}{\Q_r(x:A).H}=
 \begin{cases}
   \displaystyle\sum_{x:A}\Local{i}{H},&i=r,\\[3pt]
   \displaystyle\prod_{x:A}\Local{i}{H},&i\ne r.
 \end{cases}
 \tag{4}
\]
An endpoint term $\Gamma\vdash p:G@i$ is a term of $\D$ of type
$\Local{i}{G}$, retaining $G$ and $i$ as its interface annotation.
\end{definition}

The annotation matters: equality of a pair of local data types is not a
definition of equality of global scripts. A global script retains the shared
choice identities, the owner of each choice, and the family of interfaces.

The canonical endpoint forms expose the intended computation:
\[
 \frac{\Gamma\vdash t:R_i}
      {\Gamma\vdash\Emit_i(t):\End\langle R_j\rangle_j@i}
 \tag{5}
\]
\[
 \frac{\Gamma\vdash a:A\qquad\Gamma\vdash p:H[a/x]@r}
      {\Gamma\vdash\Send_r(a,p):\Q_r(x:A).H@r}
 \tag{6}
\]
\[
 \frac{\Gamma,x:A\vdash q:H@i\qquad i\ne r}
      {\Gamma\vdash\Recv_i(x.q):\Q_r(x:A).H@i}.
 \tag{7}
\]
Their translations into $\D$ are respectively $t$, the pair $(a,p)$, and the
function $\lambda x.q$. Arbitrary well-typed data terms at the local types are
also allowed. In particular, endpoint implementations may be abstracted over,
passed to pure functions, and instantiated using the rules of $\D$.

\paragraph{Plans and policies.}
An endpoint term describes a contingent plan. It accepts all inputs offered by
the other roles and supplies a value at each of its own reached choices. The
sum in (4) does not store continuations for alternative values of the same
earlier owned choice. Such a plan is different in representation from a full
extensive-form policy table, which also records actions at histories made
unreachable by that player's own earlier decisions. We compare their
executions in \cref{sec:policies}; we do not identify their carriers by
notation.

\subsection{Substitution}

A data substitution $\theta:\Delta\to\Gamma$ assigns a $\Delta$-term of the
appropriate type to each variable of $\Gamma$. It acts under $\Q_r$ by the
usual lifted substitution, leaving the fresh bound variable fixed.

\begin{lemma}[Local interpretation commutes with substitution]
\label{lem:substitution}
For $\Gamma\vdash G:\Script$ and $\theta:\Delta\to\Gamma$,
\[
 \Local{i}{G[\theta]}\equivdef\Local{i}{G}[\theta].
 \tag{8}
\]
Consequently, $\Gamma\vdash p:G@i$ implies
$\Delta\vdash p[\theta]:G[\theta]@i$.
\end{lemma}
\begin{proof}
Induct on the script. The terminal case is the substitution rule for $R_i$.
At a choice, (4) selects the same sum or product before and after
substitution, since $\theta$ changes no role label. Apply the corresponding
dependent sum or product substitution law and the induction hypothesis under
the lifted context. The term statement follows from substitution in $\D$.
\end{proof}

This lemma is the connection between the global binder and local dependent
typing. Sending a value instantiates one global continuation, and (8) makes
every endpoint's instantiation agree with it.
